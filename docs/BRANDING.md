# Kabosu branding and fork compatibility

Kabosu is maintained at https://github.com/getmikan/Kabosu and descends from [Sloth Clash](https://github.com/Nemu-x/SlothClash). Keep upstream credit and the GPL license when redistributing it.

## Artwork

`docs/appicon-main.png` is the 1024 × 1024 application artwork supplied for this fork. `docs/appicon.png` and `docs/readmelogo.png` carry the same image. The frontend uses a smaller copy at `frontend/src/assets/images/logo-universal.png`, and `frontend/public/favicon.png` supplies its browser icon.

`copy:desktop-appicon` seeds Wails `build/appicon.png`; `icons:windows` generates the multi-size application ICO and both colorful/mono state-aware tray sets. Wails derives macOS/Linux application icons from that same source. The tracked `trayicons/mono.png` is an alpha silhouette of the supplied citrus and leaf, suitable for macOS template rendering.

## Preserved compatibility contracts

These are internal identifiers, not unfinished display branding. Renaming them requires a separate storage/helper migration:

- `apps/sloth-clash-desktop`, Go module `SlothClashDesktop`, existing Wails service method names and native C/Objective-C symbols.
- The `SlothClash` profile/log directory, localStorage keys and companion keyring namespace. Kabosu currently shares these with an existing upstream installation; do not run both against the same profile concurrently.
- External `sloth-clash-service` binaries, service IDs, named pipes, Unix sockets, core sidecar names, helper environment variables and the Windows TUN adapter name. Their source/release repositories remain upstream dependencies.
- The parser accepts legacy `slothclash://` links to preserve existing provider integrations. Installers register **only** `kabosu://`, leaving the upstream application's handler alone.
- Historical entries in `Changelog.md` and core patch author metadata retain their original attribution.

The provider-controlled `X-Brand-Desktop-*` protocol remains supported. Operator logos may override the provider entry point; Kabosu's product icon remains the fork artwork.

## Release services

The updater now queries only `getmikan/Kabosu`. Its inherited minisign public key remains in `app_update_verify.go`; configure a fork-owned key before shipping automatic updates, as described in [UPDATES.md](UPDATES.md). No signing keys or secrets are generated by the branding change.

Optional integrations require fork-owned configuration:

- SignPath: `SIGNPATH_PROJECT_SLUG`, `SIGNPATH_SIGNING_POLICY`, `SIGNPATH_ORGANIZATION_ID` and API token.
- winget: register the initial Kabosu package, then set `WINGET_PACKAGE_IDENTIFIER` and `WINGET_TOKEN`. Upstream release manifests were removed because their installer hashes and product codes do not describe Kabosu.
- AUR: register `kabosu-bin` and configure the publishing SSH key.
- Pages/package repositories: enable GitHub Actions as the Pages source and configure package signing before advertising repository installation commands.

The old upstream UI screenshots were removed from active documentation and AppStream metadata; fresh Kabosu captures can be added after a native app run.
